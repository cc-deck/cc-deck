= Architecture

cc-deck consists of two components that work together: a Rust WASM plugin for the sidebar and a Go CLI for installation, hooks, and session management.

== Two-Component Design

Rust WASM Plugin (`cc-zellij-plugin/`)::
The sidebar that runs inside Zellij.
Compiled to WebAssembly (wasm32-wasip1) and loaded by Zellij as a plugin.
Handles rendering, navigation, smart attend, and session tracking.
Communicates with other instances via the Zellij pipe system.

Go CLI (`cc-deck/`)::
The command-line tool that users interact with directly.
Handles plugin installation, hook registration, snapshots, and the container image build pipeline.
Embeds the WASM binary so a single `cc-deck` binary installs everything.

== Plugin Permissions

Both roles run from the same WASM binary and request the same seven Zellij permissions on load.
The controller runs as a background plugin, which cannot display a permission dialog at all, so `cc-deck install` pre-populates Zellij's `permissions.kdl` cache before the plugin ever loads.
A pre-populated grant is answered immediately, without prompting the user.

Pre-population alone is not sufficient.
Zellij addresses the `PermissionRequestResult` event to a specific client, and a plugin started during the initial layout load can be handed that result before any client is ready to receive it.
The grant is then dropped in transit.

A dropped grant used to strand the plugin permanently.
The controller discards every pipe message while it is unpermissioned, so a sidebar's registration never lands, no render is ever broadcast, and the sidebar keeps showing the permission prompt on a pane that has already been made unfocusable.
Every recovery path ran through the same broken loop.

Both roles therefore drive their own recovery from a timer, which is the one signal that arrives from outside that loop.
A plugin that is still unpermissioned when a timer fires asks again and re-arms the timer.
The retry is bounded by `PERMISSION_RETRY_LIMIT`, so a request that is genuinely waiting on a human answer is never re-raised on a loop.
On a healthy start the grant has already arrived, the first tick returns early, and the recovery costs a single timer tick.

== Sync Protocol

The WASM plugin runs as a separate instance on every tab (via the layout template).
These instances synchronize session state through Zellij's pipe messaging system:

`cc-deck:sync`::
Broadcast session state to all instances.
Used when a session's activity changes.

`cc-deck:request`::
Request the latest state from other instances.

`cc-deck:hook`::
Incoming hook events from Claude Code (via the Go CLI).

`cc-deck:navigate`::
Navigation commands (switch tab, attend).

`cc-deck:attend`::
Smart attend requests.

== Hook Integration

Claude Code hooks (configured in `~/.claude/settings.json`) call the Go CLI on session events.
The CLI forwards these to the WASM plugin via Zellij's pipe system.

The flow:

1. Claude Code fires a hook event (e.g., session starts, permission request)
2. `cc-deck hook --pane-id "$ZELLIJ_PANE_ID"` runs
3. The CLI exits immediately when it is not running inside a Zellij session
4. The CLI maps the pane ID to a plugin instance
5. The plugin updates the session's state in the sidebar

Step 3 matters because `zellij pipe` succeeds when it is run from outside a Zellij session and delivers to whichever session is running.
Without that check, an agent started in a plain terminal would appear in the sidebar of an unrelated session.

A pane ID arriving on a hook event is a claim that the controller has not yet verified.
The controller therefore holds a newly created session back until the Zellij pane manifest confirms that the pane exists, and removes the session if that confirmation does not arrive.
This matters because pane IDs restart from zero in every Zellij run.
An ID carried over from an earlier run does not simply fail to match.
It addresses a different pane that is genuinely in use.

== Directory Structure

[source,text]
----
cc-deck/
├── cc-zellij-plugin/       # Rust WASM plugin
│   ├── src/
│   │   ├── main.rs         # Plugin entry, events, keybindings
│   │   ├── sidebar.rs      # Rendering (cursor, pause, help)
│   │   ├── attend.rs       # Smart attend algorithm
│   │   └── session.rs      # Session model, Activity enum
│   └── Cargo.toml
├── cc-deck/                # Go CLI
│   ├── cmd/cc-deck/        # Main entry point
│   ├── internal/
│   │   ├── cmd/            # Cobra commands
│   │   ├── plugin/         # Install, hooks, layout, embed
│   │   ├── build/          # Image pipeline
│   │   └── session/        # Snapshot management
│   └── go.mod
├── base-image/             # Base container image
├── docs/                   # Antora documentation (this site)
└── specs/                  # Feature specifications
----
