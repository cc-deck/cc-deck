= Compose Environments

Compose environments use `podman-compose` for multi-container orchestration.
Unlike the single-container `container` type, compose environments support sidecar containers for network filtering and future MCP server integration.

Compose environments are project-local.
All generated orchestration files live in a `.cc-deck/` subdirectory within the project directory.
The project directory is bind-mounted at `/workspace` by default, providing immediate bidirectional file synchronization.

== Walkthrough: Your First Compose Environment

This walkthrough takes you from an empty project directory to a running, network-filtered Claude Code session in about two minutes.

=== Step 1: Navigate to your project

[source,bash]
----
cd ~/projects/my-api
ls
# go.mod  main.go  internal/  README.md
----

=== Step 2: Create the environment

[source,bash]
----
cc-deck ws new dev --type compose
----

You will see output similar to:

----
WARNING: no image specified, using default quay.io/cc-deck/cc-deck-demo:latest
Environment "dev" created (type: compose)
----

The generated files are kept out of version control automatically.
cc-deck writes `.cc-deck/.gitignore` with an entry for `run/`, and leaves your own `.gitignore` alone.

Take a look at what was generated:

[source,bash]
----
ls -la .cc-deck/run/
# compose.yaml   env
----

The `compose.yaml` defines the session container with your project directory mounted at `/workspace`.
The `env` file contains any auto-detected credentials from your host.

=== Step 3: Attach to the session

[source,bash]
----
cc-deck ws attach dev
----

This opens a Zellij session inside the container with the cc-deck sidebar plugin loaded.
Your project files are immediately available:

[source,bash]
----
# Inside the container:
ls /workspace
# go.mod  main.go  internal/  README.md
----

Edit a file on either side (host or container) and the change appears instantly on the other side.

=== Step 4: Add network filtering

If you want to restrict which domains the session container can access, delete and recreate with filtering:

[source,bash]
----
# Detach from Zellij first (Ctrl+o d)
cc-deck ws delete dev --force
cc-deck ws new dev --type compose \
  --allowed-domains anthropic,github
----

Now the environment includes a tinyproxy sidecar.
Attach and verify filtering works:

[source,bash]
----
cc-deck ws attach dev

# Inside the container:
curl -s https://api.anthropic.com -o /dev/null -w "%{http_code}"
# 200 (or 401 without valid key, but the connection succeeds)

curl -s https://example.com -o /dev/null -w "%{http_code}"
# Connection refused (blocked by proxy)
----

=== Step 5: Manage the lifecycle

[source,bash]
----
# Detach from Zellij (Ctrl+o d)

# Check status
cc-deck ws status dev

# Stop to free resources
cc-deck ws stop dev

# Start again later
cc-deck ws start dev

# Re-attach
cc-deck ws attach dev
# Your files and Zellij session state are preserved.
----

=== Step 6: Clean up

[source,bash]
----
cc-deck ws delete dev
# Environment "dev" deleted
----

This removes all containers, the `.cc-deck/` directory, and the state records.
Your project files are untouched.

=== What you built

[source,text]
----
~/projects/my-api/              <-- your project (untouched)
  .cc-deck/
    .gitignore                  <-- ignores run/ below
    run/                        <-- generated, not tracked
      compose.yaml              <-- container orchestration
      env                       <-- credentials
      proxy/                    <-- only with --allowed-domains
        tinyproxy.conf
        whitelist
----

The session container runs your project at `/workspace` with full Claude Code tooling.
The optional proxy sidecar enforces a domain allowlist for network security.

== Creating a Compose Environment

[source,bash]
----
cd ~/projects/my-api
cc-deck ws new mydev --type compose
----

This command performs several steps automatically:

1. Detects the compose runtime (`podman-compose` or `docker compose`).
2. Generates orchestration files in `.cc-deck/run/` (compose.yaml, env, optional proxy config).
3. Detects host credentials and writes them to `.cc-deck/run/env`.
4. Starts the compose project with `podman-compose up -d`.
5. Records the environment in both the definition and state stores.

=== Storage Options

[cols="1,3"]
|===
| Type | Behavior

| `host-path` (default)
| Bind-mounts the project directory at `/workspace`. Changes are bidirectional and immediate.

| `named-volume`
| Creates a Podman named volume mounted at `/workspace`. Use `--storage named-volume` when isolation is preferred.
|===

=== Project Directory

The `--path` flag specifies which directory to use as the project root.
When omitted, the current working directory is used.

[source,bash]
----
cc-deck ws new mydev --type compose --path /home/user/projects/my-api
----

== Network Filtering

The `--allowed-domains` flag adds a tinyproxy sidecar container that filters outbound network traffic.
The session container can only reach domains in the allowlist.

[source,bash]
----
cc-deck ws new filtered --type compose --allowed-domains anthropic,github,npm
----

Domain groups are expanded using the built-in domain resolver.
You can specify built-in groups (e.g., `anthropic`, `github`), user-defined groups, or literal domain patterns.

When filtering is active:

* The session container has no direct internet access.
* All outbound traffic routes through the proxy sidecar.
* Requests to allowed domains succeed normally.
* Requests to unlisted domains are blocked.

== Credential Passthrough

Compose environments auto-detect host credentials and inject them into the session container.
The detection logic matches the container environment type.

Supported credential sources:

* `ANTHROPIC_API_KEY` for direct API access
* Google Vertex AI credentials (environment variables and ADC file)
* Amazon Bedrock credentials (access keys, session token, profile)
* Explicit credentials via `--credential KEY=VALUE`

Detection and `--credential` are not alternatives.
Detected credentials form the base set, and anything named with `--credential` is applied over them, so an explicit value wins where the two name the same variable.

Environment variable credentials are written to `.cc-deck/run/env`.
File-based credentials (like the Google ADC file) stay on the host and are bind mounted read-only at `/run/secrets/` inside the container, which keeps the host file the single source of truth after a re-authentication.

== Lifecycle Management

All standard environment lifecycle commands work with compose environments.

[source,bash]
----
# Stop the environment (frees resources, preserves state)
cc-deck ws stop mydev

# Start a stopped environment
cc-deck ws start mydev

# Delete the environment and all artifacts
cc-deck ws delete mydev

# Force-delete a running environment
cc-deck ws delete mydev --force
----

Stopping and starting preserves all files in the project directory (bind mount mode) and in the named volume (if used).

Deleting an environment removes all containers, cleans up secrets, and removes the `.cc-deck/` directory from the project.

== Project Hygiene

Creating a compose environment writes `.cc-deck/.gitignore` with an entry for `run/`.
This happens on every create, and needs no flag.

The generated artifacts under `.cc-deck/run/` are therefore ignored without any change to the project's own `.gitignore`, which cc-deck never writes to.
The rest of `.cc-deck/` stays trackable, so anything you choose to keep there can be committed normally.

== Command Reference

[source,bash]
----
# Create with all options
cc-deck ws new mydev --type compose \
  --image quay.io/cc-deck/cc-deck-demo:latest \
  --allowed-domains anthropic,github \
  --port 8080:8080 \
  --path /path/to/project \
  --credential KEY=VALUE \
  --auth auto

# Attach to the environment
cc-deck ws attach mydev

# Run a command inside the session container
cc-deck ws exec mydev -- ls /workspace

# Check status
cc-deck ws status mydev
----
