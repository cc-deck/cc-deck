= Profile Delegation for OpenShell

Profile delegation replaces direct policy generation for OpenShell targets.
Instead of assembling a complete `SandboxPolicy` from YAML components, cc-deck maps manifest declarations to OpenShell provider profile IDs.
The gateway resolves those profiles into a sandbox policy at workspace creation time.

== Architecture

The flow splits across two phases: build time and workspace creation time.

**Build time** (`cc-deck build run` or `/cc-deck.build --target openshell`):

1. The build reads agents, tools, and credentials from the manifest.
2. A static mapping table converts each identifier to one or more profile IDs.
3. MCP entries with endpoints and custom domain declarations are collected.
4. A `profiles.yaml` is embedded in the OCI image at `/etc/openshell/profiles.yaml`.

**Workspace creation time** (`cc-deck ws new --type openshell`):

1. The profile manifest is extracted from the OCI image.
2. Each profile ID is verified against the gateway.
3. Providers are created for each profile, with credentials merged for profiles that carry authentication.
4. Ephemeral profiles are imported for MCP endpoints and custom domains.
5. The `SandboxSpec` is submitted with the provider list and no explicit policy.
6. The gateway resolves profiles into the complete network policy.

== Profile Mapping

The mapping table lives in `internal/openshell/profiles.go` and covers three categories:

[cols="1,1,2",options="header"]
|===
| Category | Identifier | Profile IDs

| Agent
| `claude`
| `anthropic`, `claude-agent`

| Agent
| `opencode`
| `openai`, `opencode-agent`

| Agent
| `codex`
| `openai`, `codex-agent`

| Tool
| `python`
| `python`

| Tool
| `go`
| `golang`

| Tool
| `node` / `npm`
| `nodejs`

| Tool
| `rust` / `cargo`
| `rust`

| Credential
| `vertex`
| `vertexai`

| Always
| (any manifest)
| `github`, `gitlab`
|===

When no agents are declared, `claude` is the default.
Tool profiles from auto-detection (matched policy components) are merged with explicit manifest tools.
Duplicates are removed and the final list is sorted for deterministic output.

== Ephemeral Profiles

Two types of ephemeral profiles are imported at workspace creation time.

=== MCP Endpoints

When the manifest contains MCP server entries with `endpoint` fields, cc-deck imports a single ephemeral profile named `cc-deck-<workspace>-mcp`.
This profile contains all MCP endpoints as network endpoints and any agent binary paths.

The manifest declares MCP entries like this:

[source,yaml]
----
mcp:
  - name: my-server
    endpoint: "mcp.example.com:9090"
  - name: local-only
----

Only entries with an `endpoint` field are included in the profile manifest.
Entries without endpoints (like `local-only` above) are excluded.

=== Custom Domains

When the manifest declares `network.allowed_domains` or `network.allowed_domains_per_agent`, cc-deck imports an ephemeral profile named `cc-deck-<workspace>-custom`.
Each domain becomes a network endpoint with port 443 and HTTPS protocol.

[source,yaml]
----
network:
  allowed_domains:
    - custom.example.com
  allowed_domains_per_agent:
    claude:
      - agent-specific.io
----

Domains from both fields are merged and deduplicated before import.

== Compose Target Compatibility

Profile delegation only applies to OpenShell targets.
Compose targets continue to use `AssemblePolicy()` for full policy generation.
When a manifest declares both target types, the build produces both `profiles.yaml` (for OpenShell) and `policy.yaml` (for compose).

== Troubleshooting

=== Missing gateway profiles

If a profile ID in the manifest does not exist on the gateway, cc-deck logs a warning and continues with the profiles that are available.
The workspace may have restricted network access if required profiles are missing.

Check available profiles on the gateway:

[source,bash]
----
openshell profile list
----

=== Ephemeral profile import failures

If importing an MCP or custom domain profile fails, cc-deck logs a warning and continues without that profile.
The workspace will be created but MCP endpoints or custom domains will not be accessible.

Verify the gateway is reachable and the OpenShell SDK version is compatible:

[source,bash]
----
cc-deck ws status <workspace>
----

=== Profile manifest not found in image

If the OCI image does not contain `/etc/openshell/profiles.yaml`, workspace creation falls back to a default set of profiles based on the agents declared in the workspace definition.
Rebuild the image with `cc-deck build run` to embed the profile manifest.
