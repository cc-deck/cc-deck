# Contract: Harness Translator and Agent additions

**Feature**: 087-harness-profiles | **Status**: binding before the first translator is implemented (constitution II)

## 1. `agent.Agent` additions

Every adapter (`claude`, `codex`, `opencode`) MUST implement:

| Method | Contract |
|--------|----------|
| `Binary() string` | The executable name looked up on `PATH` by `IsInstalled()`. MUST equal the string passed to `exec.LookPath` there. Used for wrapper naming (`<Binary()>-<profile>`) and restore. |
| `InstallHooksAt(configDir string) error` | Installs or updates the cc-deck hooks for this harness rooted at `configDir` instead of the default directory. MUST be idempotent. MUST preserve foreign hooks in the same file. MUST NOT touch the default directory. When `configDir` equals the default directory it MUST behave exactly like `InstallHooks()`. If the target file is a symlink to the default directory's file (shared entry), it MUST write through the symlink and MUST NOT replace the link with a regular file. |
| `ResumeArgs(sessionID string) []string` | Arguments that resume the given session for this harness: `claude` returns `["--resume", id]`, `codex` returns `["resume", id]`, `opencode` returns `["--session", id]`. An empty `sessionID` MUST return an empty slice. |

`InstallHooks()` MUST remain equivalent to `InstallHooksAt(<default config dir>)`, where the default config dir is the directory `DetectConfig()` reports (or would report once created), so existing callers and tests are unaffected.

## 2. `profile.Translator` interface

```go
type Translator interface {
    Harness() string                                   // registry key, equals Agent.Name()
    ConfigDirEnv() string                              // e.g. "CLAUDE_CONFIG_DIR"
    IsolatedEntries() []string                         // top-level entries never shared
    SupportsLogin() bool                               // auth.login allowed
    Backends() []config.BackendType                    // allowed backends, first is default
    DefaultConfigSubdir() string                       // conventional config subdir under $HOME (e.g. ".claude")
    Render(rp ResolvedProfile) (WrapperScript, error)  // wrapper content
    PrepareConfigDir(rp ResolvedProfile, defaultDir string) (warnings []string, err error)
    ProviderType(backend config.BackendType) string    // OpenShell provider type, "" if none
    SupportsOAuthToken() bool                          // auth.oauth_token allowed (claude only), revision 2026-10-12
    AuthVars() map[AuthKind][]string                   // env vars selecting or carrying each auth kind (research R16)
}
```

### 2.1 Registry

- `profile.Register(t Translator)` panics on a duplicate `Harness()`.
- `profile.Lookup(name string) (Translator, bool)`.
- Translators self-register in `init()`, mirroring `agent.Register`.
- `profile.Lookup(h)` MUST succeed for every `agent.All()` entry, and a test enforces the pairing.

### 2.2 `Render`

- Output MUST start with `#!/bin/sh` and the marker line `# generated by cc-deck profile <name>; do not edit`.
- Output MUST contain `export CC_DECK_PROFILE='<name>'` (single-quoted) as the first export, followed by `export CC_DECK_PROFILE_COLOR='<#RRGGBB>'` with `rp.Color`, and `export CC_DECK_PROFILE_ICON='<icon>'` (empty `''` when `rp.Icon` is empty).
- Output MUST contain, directly after those exports, exactly one `unset` line naming in sorted order every variable in `AuthVars()` whose kind differs from `rp.Kind()`, and no such line when that set is empty.
- For an `OAuthToken` source, output MUST render the same check as for an `api_key` source of the same kind and export the harness token variable (`claude`: `CLAUDE_CODE_OAUTH_TOKEN`).
- Output MUST export `ConfigDirEnv()` to `$HOME/.local/share/cc-deck/profiles/<name>/<harness>` (or the OpenCode config file path) using `$HOME`, never an absolute host path.
- Output MUST export the model variable when `rp.Model` is non-empty (`claude`: `ANTHROPIC_MODEL`; `codex`: via generated `config.toml`, no export; `opencode`: via generated config, no export).
- Output MUST export every `rp.Env` entry in sorted key order, single-quoted, after the model and before credentials.
- Output MUST contain a credential reference for each `CredentialSource` of kind `env` or `file` as defined in `contracts/wrapper-script.md`, and MUST NOT contain the value of any credential.
- Output MUST end with `exec <Binary()> "$@"`.
- `Render` MUST be a pure function of `rp` (same input, same bytes), so `Sync` can compare content to decide "updated" versus "unchanged".
- `Render` MUST return an error for a `secret`-kind source (not renderable outside Kubernetes), for `Login` on a translator whose `SupportsLogin()` is false, and for `OAuthToken` on a translator whose `SupportsOAuthToken()` is false.

### 2.3 `PrepareConfigDir`

- MUST create `rp.ConfigDir` with mode 0700 if absent.
- For every top-level entry `e` of `defaultDir` not in `IsolatedEntries()`: if `ConfigDir/e` is absent, create a symlink to `defaultDir/e` (relative when both are under `$HOME`); if it is a symlink to a different target, repoint it; if it is a regular file or directory, leave it and record a warning.
- Entries in `IsolatedEntries()` MUST never be linked. If absent they are left absent, except where the harness needs a seed file (Codex `config.toml`, OpenCode config file), which the translator generates from `rp`.
- MUST be idempotent and MUST NOT delete anything.
- MUST NOT read or copy any file listed in `IsolatedEntries()` from `defaultDir`.
- After preparing, the caller invokes `Agent.InstallHooksAt(rp.ConfigDir)`; the translator MUST arrange the directory so that this call succeeds (for shared hook files this means the symlink exists).

### 2.4 Per-harness specifics

| Harness | `ConfigDirEnv` | `IsolatedEntries` | `SupportsLogin` | `SupportsOAuthToken` | `Backends` | Model mechanism | `ProviderType` |
|---------|----------------|-------------------|-----------------|----------------------|------------|-----------------|----------------|
| claude | `CLAUDE_CONFIG_DIR` | `.claude.json`, `.credentials.json`, `backups`, `statsig` | true | true | `anthropic` (default), `vertex` | `ANTHROPIC_MODEL` | `anthropic`/token/login: `claude`; `vertex`: `google-cloud` |
| codex | `CODEX_HOME` | `auth.json`, `config.toml`, `sessions` | false | false | `openai` | `model = "<m>"` in generated `config.toml` | `openai` |
| opencode | `OPENCODE_CONFIG` | the generated `opencode.json` | false | false | `openai` (default), `anthropic` | `"model": "<provider>/<m>"` in generated file | `openai` or `claude` |

`AuthVars()` per harness is the table in research R16.

Claude `.claude.json` (added 2026-10-14): Claude Code keeps account state and user configuration in one file, `$CLAUDE_CONFIG_DIR/.claude.json` (default setup: `~/.claude.json`), so it cannot be linked. `PrepareConfigDir` merges the configuration part of the default file into the profile's file on every sync: user-scope `mcpServers` (default wins by server name, profile-only servers stay) and, per project, `allowedTools`, `disabledMcpServers`, `disabledMcpjsonServers`, `enabledMcpjsonServers`, `hasClaudeMdExternalIncludesApproved`, `hasClaudeMdExternalIncludesWarningShown`, `hasTrustDialogAccepted`, `mcpContextUris` and `mcpServers`. `hasCompletedOnboarding` and `lastOnboardingVersion` are copied only when the profile file lacks them. Account fields, caches, counters and per-project session statistics are never copied. The file is written atomically with mode 0600 and only when it changes. Remote provisioning does not merge `.claude.json`.

Isolation changes: when an entry becomes isolated after an earlier sync linked it (for example `backups`), `PrepareConfigDir` and the remote `prepare.sh` remove that link to the default directory, never its target.

Credential export names per backend: `anthropic` and `openai` export `ANTHROPIC_API_KEY` / `OPENAI_API_KEY`; `vertex` exports `CLAUDE_CODE_USE_VERTEX=1`, `ANTHROPIC_VERTEX_PROJECT_ID`, `CLOUD_ML_REGION`, and `GOOGLE_APPLICATION_CREDENTIALS` pointing at the transported credentials file when `Credentials` is set.

### 2.5 Behaviors verified by contract tests (one test file exercising every registered translator)

1. `Render` output passes `sh -n` (syntax check) on the host.
2. `Render` output contains no credential value for a profile whose `env` source is set in the test process environment.
3. `Render` is deterministic across two calls.
4. `PrepareConfigDir` on a temp default dir with entries `a/`, `b.json`, plus every isolated entry, links exactly the non-isolated entries and leaves isolated ones absent (or seeded, for Codex and OpenCode).
5. `PrepareConfigDir` twice yields the same tree.
6. `Lookup(a.Name())` succeeds for every `agent.All()`.
7. `Render` output contains the `CC_DECK_PROFILE_COLOR` export and, for every auth kind the translator supports, the expected `unset` line (no variable of the profile's own kind, every variable of the other kinds).
8. An `OAuthToken` profile renders for `claude` and returns an error for every translator whose `SupportsOAuthToken()` is false.

## 3. Error contract

Errors returned from `Render` and `PrepareConfigDir` MUST be wrapped as `profile "<name>": <cause>` so `Sync` can list them per profile in `SyncResult.Skipped`.
